OpenReplay のトラッカーを設定してユーザーセッションを取得できるようになれば、プロダクトで実際に何が起きているのかを明らかにする準備は完了です。OmniSearch は、問題のデバッグ、不具合の原因の特定、ユーザー行動の詳細な理解に役立ちます。定量データと、セッションリプレイに隠れた定性的なインサイトとの橋渡しをします。

## イベントについて

OmniSearch の **Events** は、セッション中に発生するユーザーの操作やシステムの動作を表します。 

大きく 2 つのカテゴリに分かれます。**Events**（**Autocaptured:** ユーザー操作の自動トラッキング、**Custom events:** SDK を使用して送信）と、**DevTools events**（技術的なモニタリングとデバッグ）です。 

###  イベント
| **イベント名**  | **説明** |
| --- | --- |
| Click | ユーザーのクリックを記録します。 |
| Text Input | フィールドに入力されたテキストをトラッキングします。 |
| Visited URL | 訪問したページを記録します |
| Tagged Element | カスタムタグを付けた要素をトラッキングします。 |
| Custom Events | ユーザー定義のイベントで、SDK を使用して送信されます。 |


### DevTools イベント

|  **イベント名**  | **説明** |
| --- | --- |
| Network Request | ネットワークアクティビティを監視します。 |
| GraphQL | GraphQL のクエリとレスポンスを記録します。 |
| State Action | アプリケーション内の状態の変化をトラッキングします。 |
| Error Message | コンソール内のエラーメッセージをキャプチャします。 |
| Average CPU Load | CPU の平均使用率を計測します。 |
| Average Memory Usage | メモリの平均消費量をトラッキングします。 |

## フィルターについて

OmniSearch の **Filters** は、特定の条件でセッションリプレイを絞り込むのに役立ち、最も関連性の高いユーザーセッションに集中できます。イベントと組み合わせて使用することで、セッションデータ全体に対して精度の高い検索を実行できます。 

フィルターは、大きく 4 つのカテゴリに分類されます。

### ユーザーフィルター

|  **フィルター名**  | **説明** |
| --- | --- |
| User ID | 固有の識別子を使用して、特定のユーザーでフィルターします。 |
| Anonymous User ID | ログイン ID を持たないユーザーのセッションをフィルターします。 |

### セッションフィルター

|  **フィルター名**  | **説明** |
| --- | --- |
| Country | 国でセッションをフィルターします。 |
| City | 市区町村でセッションをフィルターします。 |
| State/Province | 州または省でセッションをフィルターします。 |
| Operating System (OS) | 使用されているオペレーティングシステムでセッションをフィルターします。 |
| Browser | ブラウザーの種類でセッションをフィルターします。 |
| Device | ユーザーのデバイスでセッションをフィルターします。 |
| Platform | プラットフォームの種類でセッションをフィルターします。 |
| Version ID | アプリケーションのバージョンでセッションをフィルターします。 |
| Referrer | リファラー URL に基づいてセッションをフィルターします。 |
| Duration | 長さでセッションリプレイをフィルターします。 |
| UTM Source | UTM ソースパラメーターでセッションをフィルターします。 |
| UTM Medium | UTM メディアパラメーターでセッションをフィルターします。 |
| UTM Campaign | UTM キャンペーンパラメーターでセッションをフィルターします。 |

### 問題フィルター

|  **フィルター名**  | **説明** |
| --- | --- |
| Rage Click, Dead Click, Excessive Scrolling, Mouse Thrashing | 繰り返しのクリック、壊れたボタンやリンク、過度なスクロール、不規則なマウス操作などによってユーザーが不満を感じたセッションを特定します…。 |
| Bad Request | HTTP 400 エラーが発生したセッションを特定します。 |
| Missing Resource | リソースが見つからないセッションを検出します |
| CPU Issues | CPU 使用率が高いセッションを特定します。 |
| Slow Resource | 読み込みの遅いリソースがあるセッションを特定します。 |
| Slow Page Load | ページの読み込み時間が遅いセッションを特定します。 |
| Crash | アプリまたはページがクラッシュしたセッションを特定します。 |
| Errors | アプリケーションエラーが発生したセッションを特定します。 |

### メタデータフィルター

|  **フィルター名**  | **説明** |
| --- | --- |
| Metadata key | カスタム定義のメタデータを使用して、セッションをフィルターします。未定義の場合は、メタデータの追加方法を[こちら](/tutorials/metadata)で確認してください |
