Inicia o armazenamento de mensagens em buffer sem iniciar a sessão em si. O buffer manterá os últimos 30 segundos de eventos gravados. Você pode ativar a sessão chamando `start()` ou por meio de um gatilho condicional.

## Assinatura

```ts
coldStart(startOpts?: Partial<StartOptions>, isConditional?: boolean): Promise<void>
```

### Parâmetros
Com `startOpts`, você pode personalizar diferentes aspectos da gravação:
- `userID: string`: Usado para definir manualmente o `userID` e rastreá-lo entre sessões. É um valor do tipo string e pode ser o que você quiser.
- `metadata: Record<string, string>`: Define manualmente os valores de metadados. Consulte a [seção de Metadados](/session-replay/metadata) para saber mais sobre isso.
- `forceNew: boolean`: Usado para forçar uma nova sessão após a atualização da página. Por padrão, é definido como `false`, portanto, após uma atualização, a sessão é mantida.
- `sessionHash: string`: Usado para sessões persistentes (sticky sessions). Útil se você tem uma aplicação com vários sites ou se precisa redirecionar o usuário para fora e depois de volta ao seu site (por exemplo, para um gateway de pagamento).
- `isConditional`: Decide se o tracker deve aguardar que a condição do gatilho seja atendida antes de iniciar a sessão automaticamente.

> Observação: a gravação condicional só é suportada nas nossas ofertas Cloud e Enterprise Edition.

### Valor de retorno

Este método não retorna nenhum valor.
