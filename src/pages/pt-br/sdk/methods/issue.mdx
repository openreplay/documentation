Este método pode ser usado para reportar um "evento técnico", também conhecido como "issue". Essas issues podem ser usadas para reportar informações extras sobre um problema que o tracker não consegue captar por padrão. Um bom exemplo seria o usuário tentando pagar uma compra no nosso e-commerce e recebendo um erro do gateway de pagamento. Embora o tracker possa gravar o payload com o erro, ele não o identificaria como um problema. Este método permite sinalizar esse comportamento como uma issue, para filtrar as sessões posteriormente.

<Aside type="tip">
  Também temos um tutorial detalhado sobre como rastrear eventos personalizados, que você pode conferir [aqui](/tutorials/custom-events).
</Aside>

## Assinatura

```js
issue(key: string, payload?: any): void
```

## Parâmetros

- `key: string`: O nome da chave em que os dados do evento serão salvos. Você pode usar esse valor nos campos de filtro dentro da plataforma OpenReplay.
- `payload: any`: Os dados relacionados ao evento rastreado. Você pode salvar aqui qualquer objeto serializável.

## Valor de retorno

Este método não retorna nenhum valor; você poderá ver as informações rastreadas dentro da plataforma OpenReplay.
