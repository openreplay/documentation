Com o tracker do OpenReplay configurado e capturando sessões de usuários, você está pronto para descobrir o que realmente acontece no seu produto. O OmniSearch ajuda você a depurar problemas, identificar o que está dando errado e entender o comportamento dos usuários em detalhes. Ele faz a ponte entre os dados quantitativos e os insights qualitativos escondidos nos seus session replays.

## Entendendo os eventos

Os **Events** no OmniSearch representam as interações dos usuários e os comportamentos do sistema que ocorrem durante uma sessão. 

Eles se dividem em duas categorias principais: **Events** (**Autocaptured:** rastreamento automático de interações do usuário e **Custom events:** enviados usando o SDK) e **DevTools events** (monitoramento técnico e depuração). 

###  Events
| **Nome do evento**  | **Descrição** |
| --- | --- |
| Click | Registra os cliques do usuário. |
| Text Input | Rastreia o texto digitado nos campos. |
| Visited URL | Registra as páginas visitadas |
| Tagged Element | Rastreia elementos marcados com tags personalizadas. |
| Custom Events | Eventos definidos pelo usuário, enviados usando o SDK. |


### DevTools events

|  **Nome do evento**  | **Descrição** |
| --- | --- |
| Network Request | Monitora a atividade de rede. |
| GraphQL | Registra consultas e respostas do GraphQL. |
| State Action | Rastreia mudanças de estado na sua aplicação. |
| Error Message | Captura mensagens de erro no console. |
| Average CPU Load | Mede o uso médio de CPU. |
| Average Memory Usage | Rastreia o consumo médio de memória. |

## Entendendo os filtros

Os **Filters** no OmniSearch ajudam você a refinar os session replays por critérios específicos, permitindo focar nas sessões de usuários mais relevantes. Eles funcionam em conjunto com os eventos para criar buscas precisas nos dados das suas sessões. 

Os filtros são organizados em quatro categorias principais:

### Filtros de usuário

|  **Nome do filtro**  | **Descrição** |
| --- | --- |
| User ID | Filtre usuários específicos usando seus identificadores únicos. |
| Anonymous User ID | Filtre sessões de usuários sem uma identidade logada. |

### Filtros de sessão

|  **Nome do filtro**  | **Descrição** |
| --- | --- |
| Country | Filtre sessões por país. |
| City | Filtre sessões por cidade. |
| State/Province | Filtre sessões por estado ou província. |
| Operating System (OS) | Filtre sessões pelo sistema operacional usado. |
| Browser | Filtre sessões pelo tipo de navegador. |
| Device | Filtre sessões pelo dispositivo do usuário. |
| Platform | Filtre sessões pelo tipo de plataforma. |
| Version ID | Filtre sessões pela versão da aplicação. |
| Referrer | Filtre sessões com base na URL de origem. |
| Duration | Filtre session replays pela duração. |
| UTM Source | Filtre sessões pelo parâmetro UTM source. |
| UTM Medium | Filtre sessões pelo parâmetro UTM medium. |
| UTM Campaign | Filtre sessões pelo parâmetro UTM campaign. |

### Filtros de problemas

|  **Nome do filtro**  | **Descrição** |
| --- | --- |
| Rage Click, Dead Click, Excessive Scrolling, Mouse Thrashing | Identifique sessões com frustração do usuário causada por cliques repetidos, botões ou links quebrados, rolagem excessiva, movimentos erráticos do mouse…. |
| Bad Request | Identifique sessões com erros HTTP 400. |
| Missing Resource | Encontre sessões com recursos ausentes |
| CPU Issues | Identifique sessões com alto uso de CPU. |
| Slow Resource | Identifique sessões com recursos de carregamento lento. |
| Slow Page Load | Identifique sessões com tempos de carregamento de página lentos. |
| Crash | Identifique sessões em que o app ou a página travou. |
| Errors | Identifique sessões com erros na aplicação. |

### Filtros de metadados

|  **Nome do filtro**  | **Descrição** |
| --- | --- |
| Metadata key | Use metadados definidos por você para filtrar sessões. Se ainda não houver nenhum definido, veja como adicionar metadados [aqui](/tutorials/metadata) |
