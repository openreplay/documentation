## Timing ausente

Quando o CORS está em vigor, muitos dos valores das propriedades de timing são retornados como zero, a menos que a política de acesso do servidor permita que esses valores sejam compartilhados. Isso exige que o servidor que fornece o recurso envie o cabeçalho de resposta HTTP `Timing-Allow-Origin` com um valor especificando a origem ou as origens autorizadas a obter os valores de timestamp restritos.

Isso é particularmente importante para recursos de origem cruzada (cross-origin), como aqueles carregados de um domínio diferente do que serve a página principal. Se o cabeçalho `Timing-Allow-Origin` não estiver configurado corretamente, o OpenReplay não conseguirá registrar as informações de timing desses recursos.

Por exemplo, para permitir que https://application.example.com veja as informações de timing de recursos ao fazer requisições ao backend em https://data.example.com, o backend deve incluir os seguintes cabeçalhos:

```http
Timing-Allow-Origin: https://application.example.com
```
