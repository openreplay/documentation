Lo stack di OpenReplay può essere installato su una singola macchina e un server dedicato OVHcloud, un VPS, una macchina virtuale Private Cloud o un'istanza Public Cloud è un candidato ideale. Ecco come fare.

## Ordinare il server o avviare l'istanza

Puoi usare uno qualsiasi dei seguenti prodotti OVHcloud per distribuire OpenReplay:

- Server dedicato
- VPS
- Private Cloud (all'interno di una macchina virtuale)
- Istanza Public Cloud

Prerequisiti:

- Scegli *Ubuntu Server 24.04 LTS* come sistema operativo.
- Le specifiche minime per la macchina che esegue OpenReplay sono `2 vCPUs, 8 GB of RAM, 50 GB of storage`, su un'architettura x86, altrimenti i servizi backend di OpenReplay semplicemente non si avvieranno. Dovrebbero bastare per un volume di traffico basso o moderato. Se prevedi un traffico elevato, dovresti scalare a partire da qui.
- Un indirizzo IP pubblico che punti al tuo server/alla tua istanza.

## Distribuire OpenReplay

1. Assicurati che il tuo server/la tua istanza sia avviato/a, quindi connettiti ad esso/a tramite SSH come root

2. Installa OpenReplay indicando il dominio su cui verrà eseguito (ad es. DOMAIN_NAME=openreplay.mycompany.com):

```bash
sudo wget https://raw.githubusercontent.com/openreplay/openreplay/main/scripts/helmcharts/openreplay-cli -O /bin/openreplay 
sudo chmod +x /bin/openreplay
openreplay -i DOMAIN_NAME
```

## Configurare TLS/SSL

OpenReplay gestisce dati sensibili degli utenti e richiede quindi HTTPS per funzionare. Questo è obbligatorio, altrimenti il tracker semplicemente non inizierebbe a registrare. Lo stesso vale per la dashboard: senza HTTPS non potrai riprodurre le sessioni degli utenti.

Devi quindi importare (o generare) il tuo certificato SSL.

1. Per prima cosa, vai nel pannello di controllo OVHcloud in 'Web cloud' > 'Domain names' > il tuo dominio (ad es. mycompany.com) > 'DNS zone' (o sul tuo altro provider DNS) e crea un `A Record`. Usa il dominio che hai indicato in precedenza durante la fase di installazione e fallo puntare al server/all'istanza tramite il suo IP pubblico.

2. Se importi un tuo certificato, crea un secret SSL con il seguente comando: `kubectl create secret tls openreplay-ssl -n app --key="private_key_file.pem" --cert="certificate.crt"`.

> **Nota:** Se non hai un certificato, generane uno con rinnovo automatico per il tuo sottodominio (quello indicato durante l'installazione) usando Let's Encrypt. Basta connettersi al server/all'istanza di OpenReplay, eseguire `cd /var/lib/openreplay/openreplay/scripts/helmcharts && bash certmanager.sh` e seguire i passaggi.

3. Se vuoi abilitare il reindirizzamento da http a https (consigliato), rimuovi il commento dal blocco seguente, nella sezione `ingress-nginx`, in `/var/lib/openreplay/vars.yaml`:
   
```yaml
ingress-nginx: &ingress-nginx
  controller:
    config:
      ssl-redirect: true
      force-ssl-redirect: true
```

Vale la pena ricordare che il nostro `ingress-nginx` viene eseguito per impostazione predefinita sulle porte `80|443`, ma questo può essere facilmente modificato, se necessario, in `vars.yaml`:

```yaml
ingress-nginx: &ingress-nginx
  controller:
    service:
      ports:
        http: 80
        https: 443
```

4. Infine, reinstalla l'NGINX di OpenReplay:

```bash
openreplay -R
```

Ora è tutto pronto: OpenReplay dovrebbe essere raggiungibile sul tuo sottodominio. Puoi creare un account visitando la pagina `/signup` (ad es. openreplay.mycompany.com/signup).
