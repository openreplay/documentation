Lo stack di OpenReplay può essere installato su una singola macchina e Microsoft Azure è un candidato ideale. Ecco come fare.

## Avviare una VM

1. Accedi al tuo portale
2. Fai clic su 'Virtual Machine' se è disponibile nella schermata principale. In caso contrario, fai clic su 'Create a Resource' > 'Compute' > 'Virtual Machine'
3. Nella pagina 'Virtual Machine', fai clic su 'Add' se non vieni reindirizzato automaticamente alla pagina di creazione
4. Scegli *Ubuntu Server 24.04 LTS* come 'Image'
4. Scegli le specifiche della tua VM. Le risorse **minime** sono `2 vCPUs, 8 GB of RAM, 50 GB of storage`, su un'architettura x86, altrimenti i servizi backend di OpenReplay semplicemente non si avvieranno. Le specifiche minime bastano per un volume di traffico basso o moderato. Se prevedi un traffico elevato, dovresti scalare a partire da qui.
5. Abilita le porte HTTP (80), HTTPS (443) e SSH (22) e prendi nota dello `username`
6. Fai clic su 'Review + create'

## Distribuire OpenReplay

1. Assicurati che la tua VM sia `Running`, quindi connettiti ad essa:

```bash
## From your terminal
SSH_KEY=~/Downloads/openreplay-key.pem ## only if you've previously created an SSH key
chmod 400 $SSH_KEY
INSTANCE_IP=REPLACE_WITH_INSTANCE_PUBLIC_IP
ssh <username>@$INSTANCE_IP ## or ssh -i $SSH_KEY <username>@$INSTANCE_IP if you have a key
```

2. Installa OpenReplay indicando il dominio su cui verrà eseguito (ad es. DOMAIN_NAME=openreplay.mycompany.com):

```bash
sudo wget https://raw.githubusercontent.com/openreplay/openreplay/main/scripts/helmcharts/openreplay-cli -O /bin/openreplay 
sudo chmod +x /bin/openreplay
openreplay -i DOMAIN_NAME
```

## Configurare TLS/SSL

OpenReplay gestisce dati sensibili degli utenti e richiede quindi HTTPS per funzionare. Questo è obbligatorio, altrimenti il tracker semplicemente non inizierebbe a registrare. Lo stesso vale per la dashboard: senza HTTPS non potrai riprodurre le sessioni degli utenti.

Devi quindi generare (o importare) il tuo certificato SSL.

1. Per prima cosa, vai su Azure DNS (o sul tuo altro provider DNS) e crea un `A Record`. Usa il dominio che hai indicato in precedenza durante la fase di installazione e fallo puntare alla VM tramite il suo IP pubblico.

2. Se importi un tuo certificato, crea un secret SSL con il seguente comando: `kubectl create secret tls openreplay-ssl -n app --key="private_key_file.pem" --cert="certificate.crt"`.

> **Nota:** Se non hai un certificato, generane uno con rinnovo automatico per il tuo sottodominio (quello indicato durante l'installazione) usando Let's Encrypt. Basta connettersi alla VM di OpenReplay, eseguire `cd /var/lib/openreplay/openreplay/scripts/helmcharts && bash certmanager.sh` e seguire i passaggi.

3. Se vuoi abilitare il reindirizzamento da http a https (consigliato), rimuovi il commento dal blocco seguente, nella sezione `ingress-nginx`, in `/var/lib/openreplay/vars.yaml`:
   
```yaml
ingress-nginx: &ingress-nginx
  controller:
    config:
      ssl-redirect: true
      force-ssl-redirect: true
```

Vale la pena ricordare che il nostro `ingress-nginx` viene eseguito per impostazione predefinita sulle porte `80|443`, ma questo può essere facilmente modificato, se necessario, in `vars.yaml`:

```yaml
ingress-nginx: &ingress-nginx
  controller:
    service:
      ports:
        http: 80
        https: 443
```

4. Infine, reinstalla l'NGINX di OpenReplay:

```bash
openreplay -R
```

Ora è tutto pronto: OpenReplay dovrebbe essere raggiungibile sul tuo sottodominio. Puoi creare un account visitando la pagina `/signup` (ad es. openreplay.mycompany.com/signup).

> **Nota:** Per una maggiore sicurezza, puoi anche eseguire l'istanza di OpenReplay dietro un Azure Load Balancer. Consulta la [documentazione di Azure LB](https://docs.microsoft.com/en-us/azure/load-balancer/load-balancer-overview) per maggiori dettagli.
