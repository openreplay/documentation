Esistono due approcci diversi per integrare OpenReplay in un'app Electron.

Qualunque approccio tu scelga, dovrai controllare le impostazioni CSP per consentire le seguenti API:
- WebWorkers (usati per archiviare, codificare e inviare i batch di messaggi)
- Websockets (usati nel plugin assist per trasmettere le sessioni in tempo reale)
- Peers (usati nel plugin assist per le chiamate)

## Aggiungere il codice dello snippet

Puoi aggiungere il codice dello snippet di OpenReplay direttamente nella radice del file HTML della tua app.
È il modo più semplice, ma comporta anche tutte le limitazioni dello snippet JS.

## Usare la libreria NPM

Se usi React, Angular o Vue, puoi seguire esattamente lo stesso approccio e creare l'istanza del tracker nel processo di
rendering all'interno della tua app. In questo modo potrai usare tutte le funzionalità di OpenReplay, inclusi tutti i plugin.

Per usare l'API del tracker al di fuori del contesto di rendering, dovrai usare l'IPC per attivare le azioni tramite gli eventi
che invii dal processo principale.

## Usare il plugin Assist


Nel caso del plugin Tracker-Assist, dovrai aggiungere la proprietà `socketHost`, che deve puntare al tuo ingest point
senza il suffisso `/ingest`, per correggere il routing WS predefinito.

per la libreria NPM:
```js
new Tracker({ ingestPoint: 'https://mywebsite.com/ingest' })

// ...

// or https://app.openreplay.com if you're using SaaS version
tracker.use(trackerAssist({ socketHost: 'https://mywebsite.com' }))
```

per lo snippet di codice:
```js
  var initOpts = {
    projectKey: "...",
		ingestPoint: "https://mywebsite.com/ingest",
    assistSocketHost: "https://mywebsite.com"
  };
```

In caso contrario, il WS tenterà di creare una connessione su `ws://file/ingest`, che fallirà.
