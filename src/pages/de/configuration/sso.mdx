Single Sign-On (über SAML2) ist nur in der OpenReplay Enterprise Edition verfügbar.

## Konfiguration des Identity Providers (IDP)

Erstellen Sie im Dashboard Ihres Identity Providers eine neue App mit dem Namen `openreplay` (Sie können dieses <a href="https://docs.openreplay.com/static/OpenReplay.png" target="_blank">Symbol</a> verwenden). Legen Sie auf der Konfigurationsseite den folgenden Wert fest (ersetzen Sie dabei <code>{initialValues.domain}</code> durch den richtigen Wert, zum Beispiel `https://openreplay.mycompany.com`):

| Variable | Wert |
|----------|-------------|
| ACS URL (auch Single Sign On URL oder Consumer URL genannt) | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/>/api/sso/saml2/acs/</code> |
| Entity ID (auch Audience genannt) | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/>/api/sso/saml2/metadata/</code> |
| Single Logout URL (auch SLO URL genannt) | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/>/api/sso/saml2/sls/</code> (optional) |
| Name ID (lässt sich manchmal im Bereich 'Attribute Statements' oder 'Parameters' konfigurieren) | `Email` oder `EmailAddress` oder `urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress`, abhängig von Ihrem Identity Provider |
| SAML initiator | Setzen Sie ihn auf `Service Provider` (optional) |

Definieren Sie im Bereich 'Attribute Statements' oder 'Parameters' die folgenden Felder:

| Feld | Wert |
|----------|-------------|
| tenantKey | <code><ORDynamicCode id="tenantKey" initialValue={initialValues.tenantKey} client:idle/></code> Den Wert finden Sie im Dashboard unter 'Preferences' > 'Account' (dieses Attribut darf nicht hinzugefügt werden, wenn Sie unseren Cloud-Dedicated-Tarif nutzen) |
| firstName | `user.firstName` |
| lastName |  `user.lastName` |
| internalId | Interne ID oder `user.email` (die Benutzer-ID in Ihrem Identitätsmanagementsystem) (optional) |
| groups | Repräsentiert die Rolle und die Administratorrechte des Benutzers in OpenReplay; je nach Identity Provider kann dies `user.role` oder `group` usw. sein (optional, Standard = `member` ohne Administratorrechte). Um die Verwaltung der OpenReplay-Rollen auf Seiten des IdP zu vereinfachen, können Sie eine Gruppe namens OpenReplay-admin mit den Benutzern mit Administratorrechten und eine Gruppe namens OpenReplay-member mit den Benutzern mit der Rolle 'member' anlegen |

Sie sollten nun alle erforderlichen Werte für den nächsten Schritt bzw. Abschnitt haben.

## SSO-Konfiguration (SAML2)

Wenn Sie unseren Cloud-Dedicated-Tarif nutzen, rufen Sie die [Console](https://console.openreplay.com) auf, klicken Sie auf die Instanz und legen Sie die Variablen im Abschnitt SSO fest.

Wenn Sie hingegen unsere Enterprise Edition betreiben, führen Sie `openreplay -e` aus, entfernen Sie die Kommentarzeichen der folgenden Umgebungsvariablen im Abschnitt `chalice` und passen Sie sie an:

| Variable | Beschreibung |
|----------|-------------|
| idp_entityId | Die `entityId` Ihres Identity Providers, auch als `Issuer URL` bezeichnet |
| idp_sso_url | Der `singleSignOnService` Ihres Identity Providers, auch als `SAML 2.0 Endpoint (HTTP)` bezeichnet |
| idp_x509cert | Das `x509cert`; es muss ein einzeiliger String ohne Zeilenumbrüche sein. Sie können <a href="https://www.samltool.com/format_x509cert.php" title="EIN X509-ZERTIFIKAT FORMATIEREN" target="_blank">dieses Tool</a> verwenden, um Ihren Wert zu formatieren |
| idp_name | Der Name des Identity Providers (optional) |
| idp_sls_url | Der `singleLogoutService` Ihres Identity Providers, auch als `SLO Endpoint (HTTP)` bezeichnet (optional) |
| enforce_SSO | Wenn auf `true` gesetzt, werden alle Anmeldungen mit Benutzername und Passwort blockiert (optional, Standard=`false`) |
| idp_group_prefixes | Die Präfixe der IdP-Gruppennamen (optional, Standard=`OpenReplay-,or-`) |

Speichern Sie anschließend und beenden Sie den Editor mit `:wq`, damit die Änderungen wirksam werden:

## OpenReplay-Zertifikat

Dieser Schritt ist optional: Für zusätzliche SSO-Sicherheit können Sie ein x509-Zertifikat hinzufügen:

1. Führen Sie diesen Befehl auf Ihrem Server oder einem sicheren Rechner aus (die Gültigkeitsdauer Ihres Zertifikats können Sie nach Bedarf anpassen):
```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout openreplay-sso.key -out openreplay-sso.crt
```
2. Führen Sie auf Ihrem Server `openreplay -e` aus
3. Fügen Sie im Abschnitt `chalice` die folgenden Umgebungsvariablen hinzu:
- **sp_crt**: muss ein einzeiliger String ohne Zeilenumbrüche aus der generierten Datei 'openreplay-sso.crt' sein (Sie können <a href="https://www.samltool.com/format_x509cert.php" title="EIN X509-ZERTIFIKAT FORMATIEREN" target="_blank">dieses Tool</a> verwenden, um Ihren Wert zu formatieren)
- **sp_key**: muss ein einzeiliger String ohne Zeilenumbrüche aus der generierten Datei 'openreplay-sso.key' sein
4. Speichern Sie und beenden Sie den Editor mit `:wq`, damit die Änderungen wirksam werden
5. Fügen Sie die generierte Datei 'openreplay-sso.crt' zur Anwendungskonfiguration Ihres Identity Providers hinzu

1. Melden Sie sich in Ihrem Okta-Administrations-Dashboard an und gehen Sie zu 'Applications' > 'Applications'
2. Klicken Sie auf 'Create new app integration', wählen Sie SAML 2.0 und klicken Sie auf 'Next'

4. Setzen Sie:
 - **Single sign on URL** auf <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/>/api/sso/saml2/acs/</code>
 - **Audience URI (SP Entity ID)** auf <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/>/api/sso/saml2/metadata/</code>
 - **Name ID format** auf `EmailAddress`
5. Klicken Sie auf Next, wählen Sie 'This is an internal app that we have created' und klicken Sie dann auf 'Finish'

 - **tenantKey**: Format `Basic`; setzen Sie den Wert auf <code><ORDynamicCode id="tenantKey" initialValue={initialValues.tenantKey} client:idle/></code>, zu finden im OpenReplay-Dashboard unter 'Preferences' > 'Account' (dieses Attribut darf nicht hinzugefügt werden, wenn Sie unseren Cloud-Dedicated-Tarif nutzen)

 - **lastName**: Format `Basic`; setzen Sie den Wert auf `user.lastName`
 - **internalId**: Format `Basic`; setzen Sie den Wert auf `user.email`
8. Definieren Sie das folgende Feld unter 'Group Attribute Statement' (dies ist optional):
 - **groups**: Format `Basic`, Filter `Match Regex`, Wert `OpenReplay-*` (oder Sie geben je nach Bedarf einen anderen Filter und Regex an)

   - **idp_entityId**: Identity Provider Issuer
   - **idp_sso_url**: Identity Provider Single Sign-On URL

## SCIM-Provisionierung (System for Cross-domain Identity Management)

OpenReplay unterstützt die Provisionierung von Benutzeridentitäten in der Enterprise Edition.

Um den SCIM-Dienst von OpenReplay anzubinden, aktivieren Sie einfach die SCIM-Provisionierung im Dashboard Ihres Identity Providers. Bitte legen Sie die folgenden Werte fest, damit die Integration reibungslos funktioniert:

| Variable | Beschreibung |
|----------|-------------|
| SCIM connector base URL | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/></code>/api/sso/scim/v2/ |
| User unique identifier field name | `email` |
| Support provisioning actions | Push new users, Push profile updates, Push groups |
| Authentication mode | OAuth2 |
| Access token endpoint | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/></code>/api/sso/scim/v2/token/ |
| Authorization endpoint | <code><ORDynamicCode id="domain" initialValue={initialValues.domain} client:idle/></code>/api/sso/scim/v2/authorize/ |
| Client id | <code><ORDynamicCode id="tenantKey" initialValue={initialValues.tenantKey} client:idle/></code> Den Wert finden Sie im Dashboard unter 'Preferences' > 'Account' |
| Client secret | Den Wert erhalten Sie, indem Sie diese Abfrage in Ihrer Postgres-Datenbank ausführen: <code>SELECT tenant_secret FROM tenants WHERE tenant_key = '<code><ORDynamicCode id="tenantKey" initialValue={initialValues.tenantKey} client:idle/></code>';</code> |

Nachdem Sie diese Werte festgelegt haben, folgen Sie den Hinweisen im Dashboard Ihres Identity Providers, um die Integration zu testen und die Anwendung zu autorisieren.

[Optional] Führen Sie `openreplay -e` aus, suchen Sie `chalice/environment` und definieren Sie die Variable `SCIM_ALLOWED_REDIRECT_HOSTS` mit dem bzw. den Host(s) Ihres IdP; standardmäßig ist sie auf `.okta.com` gesetzt. Wenn Sie sich bei Ihrem Host nicht sicher sind oder einen strengeren Wert wünschen, können Sie versuchen, Ihren IdP zu authentifizieren, und im Log von chalice nach dem ausgegebenen Wert suchen.

Anschließend können Sie Benutzeridentitäten mit OpenReplay als SCIM Service Provider provisionieren.

> **Hinweis:** OpenReplay fungiert zwar als SCIM Service Provider, unterstützt aber nicht die Aufteilung von Benutzern auf mehrere Gruppen (d. h. jeder Benutzer kann nur zu einer Gruppe gehören). Wird dies nicht beachtet, kann einem Benutzer unter Umständen eine geringere oder größere Anzahl an Projekten als erwartet zugewiesen werden und er kann in der OpenReplay-Anwendung weniger oder mehr Berechtigungen haben.

## Fehler

### Die Antwort wurde über http statt https empfangen

Dies kommt sehr häufig vor und liegt daran, dass der Header 'X-Forwarded-Proto' in der Anfrage fehlt. Stellen Sie zur Behebung sicher, dass der Load Balancer den Header korrekt an das OpenReplay-Backend weiterleitet, führen Sie `openreplay -e` aus und entfernen Sie im Abschnitt `ingress-nginx > config` das Kommentarzeichen der Zeile `use-forwarded-headers: true`.
