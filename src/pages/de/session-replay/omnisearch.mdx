Sobald der OpenReplay-Tracker eingerichtet ist und Benutzersitzungen erfasst, können Sie herausfinden, was in Ihrem Produkt wirklich passiert. OmniSearch unterstützt Sie dabei, Probleme zu debuggen, Fehlerursachen zu erkennen und das Benutzerverhalten im Detail zu verstehen. Sie verbindet quantitative Daten mit den qualitativen Erkenntnissen, die in Ihren Session Replays stecken.

## Ereignisse verstehen

**Events** in OmniSearch stehen für Benutzerinteraktionen und Systemverhalten, die während einer Sitzung auftreten. 

Sie gliedern sich in zwei Hauptkategorien: **Events** (**Autocaptured:** automatische Erfassung von Benutzerinteraktionen und **Custom events:** über das SDK gesendet) und **DevTools events** (technische Überwachung und Fehlersuche). 

###  Ereignisse
| **Ereignisname**  | **Beschreibung** |
| --- | --- |
| Click | Erfasst Klicks der Benutzer. |
| Text Input | Erfasst Text, der in Felder eingegeben wird. |
| Visited URL | Protokolliert besuchte Seiten |
| Tagged Element | Erfasst benutzerdefiniert markierte Elemente. |
| Custom Events | Benutzerdefinierte Ereignisse, die über das SDK gesendet werden. |


### DevTools-Ereignisse

|  **Ereignisname**  | **Beschreibung** |
| --- | --- |
| Network Request | Überwacht die Netzwerkaktivität. |
| GraphQL | Protokolliert GraphQL-Abfragen und -Antworten. |
| State Action | Erfasst Zustandsänderungen in Ihrer Anwendung. |
| Error Message | Erfasst Fehlermeldungen in der Konsole. |
| Average CPU Load | Misst die durchschnittliche CPU-Auslastung. |
| Average Memory Usage | Erfasst den durchschnittlichen Speicherverbrauch. |

## Filter verstehen

**Filters** in OmniSearch helfen Ihnen, Session Replays nach bestimmten Kriterien einzugrenzen, sodass Sie sich auf die relevantesten Benutzersitzungen konzentrieren können. Zusammen mit Ereignissen ermöglichen sie präzise Suchen in Ihren Sitzungsdaten. 

Filter sind in vier Hauptkategorien unterteilt:

### Benutzerfilter

|  **Filtername**  | **Beschreibung** |
| --- | --- |
| User ID | Filtert nach bestimmten Benutzern anhand ihrer eindeutigen Kennungen. |
| Anonymous User ID | Filtert Sitzungen von Benutzern ohne angemeldete Identität. |

### Sitzungsfilter

|  **Filtername**  | **Beschreibung** |
| --- | --- |
| Country | Filtert Sitzungen nach Land. |
| City | Filtert Sitzungen nach Stadt. |
| State/Province | Filtert Sitzungen nach Bundesstaat oder Provinz. |
| Operating System (OS) | Filtert Sitzungen nach dem verwendeten Betriebssystem. |
| Browser | Filtert Sitzungen nach Browsertyp. |
| Device | Filtert Sitzungen nach dem Gerät des Benutzers. |
| Platform | Filtert Sitzungen nach Plattformtyp. |
| Version ID | Filtert Sitzungen nach der Version der Anwendung. |
| Referrer | Filtert Sitzungen anhand der verweisenden URL. |
| Duration | Filtert Session Replays nach ihrer Dauer. |
| UTM Source | Filtert Sitzungen nach dem UTM-Parameter „source“. |
| UTM Medium | Filtert Sitzungen nach dem UTM-Parameter „medium“. |
| UTM Campaign | Filtert Sitzungen nach dem UTM-Parameter „campaign“. |

### Problemfilter

|  **Filtername**  | **Beschreibung** |
| --- | --- |
| Rage Click, Dead Click, Excessive Scrolling, Mouse Thrashing | Erkennt Sitzungen, in denen Benutzer frustriert sind – durch wiederholte Klicks, defekte Schaltflächen oder Links, übermäßiges Scrollen oder unregelmäßige Mausbewegungen…. |
| Bad Request | Erkennt Sitzungen mit HTTP-400-Fehlern. |
| Missing Resource | Findet Sitzungen mit fehlenden Ressourcen |
| CPU Issues | Erkennt Sitzungen mit hoher CPU-Auslastung. |
| Slow Resource | Erkennt Sitzungen mit langsam ladenden Ressourcen. |
| Slow Page Load | Erkennt Sitzungen mit langen Seitenladezeiten. |
| Crash | Erkennt Sitzungen, in denen die App oder die Seite abgestürzt ist. |
| Errors | Erkennt Sitzungen mit Anwendungsfehlern. |

### Metadatenfilter

|  **Filtername**  | **Beschreibung** |
| --- | --- |
| Metadata key | Verwenden Sie benutzerdefinierte Metadaten, um Sitzungen zu filtern. Falls keine definiert sind, erfahren Sie [hier](/tutorials/metadata), wie Sie Metadaten hinzufügen können |
