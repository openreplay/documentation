Der OpenReplay-Stack lässt sich auf einem einzelnen Rechner installieren, und Microsoft Azure ist dafür bestens geeignet. So gehen Sie vor.

## Eine VM starten

1. Melden Sie sich in Ihrem Portal an
2. Klicken Sie auf 'Virtual Machine', falls dies auf dem Startbildschirm angezeigt wird. Andernfalls klicken Sie auf 'Create a Resource' > 'Compute' > 'Virtual Machine'
3. Klicken Sie auf der Seite 'Virtual Machine' auf 'Add', falls Sie nicht automatisch zur Erstellungsseite weitergeleitet werden
4. Wählen Sie *Ubuntu Server 24.04 LTS* als 'Image'
4. Wählen Sie die Spezifikationen Ihrer VM. Die **Mindestanforderungen** sind `2 vCPUs, 8 GB of RAM, 50 GB of storage` auf einer x86-Architektur, andernfalls starten die OpenReplay-Backend-Dienste schlicht nicht. Die Mindestspezifikationen genügen für ein geringes bis mittleres Aufkommen. Wenn Sie viel Traffic erwarten, sollten Sie von hier aus skalieren.
5. Aktivieren Sie die Ports HTTP (80), HTTPS (443) und SSH (22) und notieren Sie sich den `username`
6. Klicken Sie auf 'Review + create'

## OpenReplay bereitstellen

1. Stellen Sie sicher, dass Ihre VM den Status `Running` hat, und verbinden Sie sich dann mit ihr:

```bash
## From your terminal
SSH_KEY=~/Downloads/openreplay-key.pem ## only if you've previously created an SSH key
chmod 400 $SSH_KEY
INSTANCE_IP=REPLACE_WITH_INSTANCE_PUBLIC_IP
ssh <username>@$INSTANCE_IP ## or ssh -i $SSH_KEY <username>@$INSTANCE_IP if you have a key
```

2. Installieren Sie OpenReplay, indem Sie die Domain angeben, unter der es laufen soll (z. B. DOMAIN_NAME=openreplay.mycompany.com):

```bash
sudo wget https://raw.githubusercontent.com/openreplay/openreplay/main/scripts/helmcharts/openreplay-cli -O /bin/openreplay 
sudo chmod +x /bin/openreplay
openreplay -i DOMAIN_NAME
```

## TLS/SSL konfigurieren

OpenReplay verarbeitet sensible Benutzerdaten und setzt daher HTTPS voraus. Das ist zwingend erforderlich, sonst würde der Tracker schlicht keine Aufzeichnung starten. Dasselbe gilt für das Dashboard: Ohne HTTPS können Sie keine Benutzersitzungen wiedergeben.

Sie müssen daher ein eigenes SSL-Zertifikat erzeugen (oder mitbringen).

1. Öffnen Sie zunächst Azure DNS (oder Ihren anderen DNS-Anbieter) und legen Sie einen `A Record` an. Verwenden Sie die Domain, die Sie zuvor im Installationsschritt angegeben haben, und lassen Sie sie über die öffentliche IP-Adresse auf die VM zeigen.

2. Wenn Sie ein eigenes Zertifikat mitbringen, erstellen Sie mit dem folgenden Befehl ein SSL-Secret: `kubectl create secret tls openreplay-ssl -n app --key="private_key_file.pem" --cert="certificate.crt"`.

> **Hinweis:** Wenn Sie kein Zertifikat haben, erzeugen Sie mit Let's Encrypt ein sich automatisch erneuerndes Zertifikat für Ihre Subdomain (die bei der Installation angegebene). Verbinden Sie sich dazu einfach mit der OpenReplay-VM, führen Sie `cd /var/lib/openreplay/openreplay/scripts/helmcharts && bash certmanager.sh` aus und folgen Sie den Schritten.

3. Wenn Sie die Weiterleitung von HTTP auf HTTPS aktivieren möchten (empfohlen), entfernen Sie in `/var/lib/openreplay/vars.yaml` die Kommentarzeichen vor dem folgenden Block im Abschnitt `ingress-nginx`:
   
```yaml
ingress-nginx: &ingress-nginx
  controller:
    config:
      ssl-redirect: true
      force-ssl-redirect: true
```

Beachten Sie, dass unser `ingress-nginx` standardmäßig auf den Ports `80|443` läuft. Das lässt sich bei Bedarf jedoch einfach in `vars.yaml` ändern:

```yaml
ingress-nginx: &ingress-nginx
  controller:
    service:
      ports:
        http: 80
        https: 443
```

4. Installieren Sie abschließend OpenReplay NGINX neu:

```bash
openreplay -R
```

Damit ist alles erledigt: OpenReplay sollte nun unter Ihrer Subdomain erreichbar sein. Sie können ein Konto erstellen, indem Sie die Seite `/signup` aufrufen (z. B. openreplay.mycompany.com/signup).

> **Hinweis:** Für zusätzliche Sicherheit können Sie die OpenReplay-Instanz auch hinter einem Azure Load Balancer betreiben. Weitere Informationen finden Sie in der [Azure-LB-Dokumentation](https://docs.microsoft.com/en-us/azure/load-balancer/load-balancer-overview).
