Mit dieser Methode können Sie ein „technisches Ereignis“ melden, auch „Issue“ genannt. Mit diesen Issues lassen sich zusätzliche Informationen zu einem Problem melden, das der Tracker standardmäßig nicht erkennen kann. Ein gutes Beispiel: Ein Benutzer versucht, in unserem E-Commerce-Shop einen Kauf zu bezahlen, und erhält vom Zahlungsanbieter eine Fehlermeldung. Der Tracker kann die Payload mit dem Fehler zwar aufzeichnen, würde sie aber nicht als Problem erkennen. Mit dieser Methode können Sie dieses Verhalten als Issue markieren, um Sitzungen anschließend gezielter zu filtern.

<Aside type="tip">
  Wir haben außerdem ein ausführliches Tutorial zum Tracken von Custom Events, das Sie sich [hier](/tutorials/custom-events) ansehen können.
</Aside>

## Signatur

```js
issue(key: string, payload?: any): void
```

## Parameter

- `key: string`: Der Name des Schlüssels, unter dem die Daten des Ereignisses gespeichert werden. Sie können diesen Wert in den Filterfeldern der OpenReplay-Plattform verwenden.
- `payload: any`: Die Daten zum getrackten Ereignis. Hier können Sie ein beliebiges serialisierbares Objekt speichern.

## Rückgabewert

Diese Methode gibt keinen Wert zurück; die getrackten Informationen sind anschließend in der OpenReplay-Plattform einsehbar.
